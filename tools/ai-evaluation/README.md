# Nonfinancial ERA evaluation operator — development implementation

This pilot evaluates an **untrained, transparent six-hour arithmetic-mean reference model** against a latest-observation persistence baseline. It is not an identified customer's model, universal certification, execution proof or a paid prediction market. Models, inference, original datasets and private inputs remain off-chain. No trained model or operational identity has been commissioned.

The selected engineering contract is `era-station-temperature-v1`: KJFK, temperature ≥25°C at 12:00 UTC on the target day. Schedule and finalize the forecast before 06:00 UTC that day. Outcome collection starts at 14:00 UTC. Choose the closest valid observation within ±30 minutes of noon; earlier timestamp wins ties. Accept only station KJFK, `wmoUnit:degC`, finite temperature, `qualityControl=V`. Conflicting duplicate timestamps are excluded. Reject incomplete pagination. If no usable evidence is available by 14:00 UTC the following day, append an unavailable/Inconclusive result. Late evidence may be retained as a correction but must not silently convert an original missing-data result into an on-time performance result. Revision 0 is immutable; at most 32 evidence revisions fit the runtime extension. Further corrections need an explicit extension, never deletion of history.

`evaluation.py terms` prints the exact terms and model manifest. `reference_model.py` is hashed into that manifest. The existing model hash must match the manifest SHA256 and be approved. Changing registered artifact/URI invalidates approval in the nonfinancial runtime. A prediction envelope commits model version/artifact, original input-document hash, exact timing, terms hash, forecast, baseline and fixture classification. **Hash the exact committed UTF-8 JSON bytes. Do not parse/re-serialize them in another language before hashing** (for example, `20.0` and `20` differ). The runtime preserves the commitment; it does not execute the model or verify the weather. Existing prediction IDs and records remain, with new binding/request/evidence maps. No certificate or prediction token is created.

The independent reviewer must be an application-authorized account distinct from the model owner and submitter. This account separation is not proof of independent control or trustworthy evidence. The collector must run separately under the agreed operational responsibility. Raw weather data is public; future private inputs must use appropriately randomized commitments and private evidence storage, not published predictable raw-value hashes. This pilot does not ingest private data.

## Run locally

Python 3 standard library only. No secrets or paid services are required for fixture tests:

```sh
python3 -m unittest discover -s tools/ai-evaluation -v
python3 tools/ai-evaluation/evaluation.py --journal /tmp/era-evaluation.sqlite terms
python3 tools/ai-evaluation/evaluation.py --journal /tmp/era-evaluation.sqlite schedule --model-id 0 --day YYYY-MM-DD
python3 tools/ai-evaluation/collect_nws.py --start UTC_START --end UTC_END --user-agent 'OWNER-PROVIDED-CONTACT' --output /tmp/weather-capture.json
python3 tools/ai-evaluation/evaluation.py --journal /tmp/era-evaluation.sqlite prepare --request REQUEST_SHA256 --input /tmp/weather-capture.json --uri IMMUTABLE_ENVELOPE_URI --expires-block REVIEWED_FUTURE_BLOCK
python3 tools/ai-evaluation/evaluation.py --journal /tmp/era-evaluation.sqlite history
python3 tools/ai-evaluation/evaluation.py --journal /tmp/era-evaluation.sqlite html > /tmp/evaluation-history.html
```

Choose a future block expiry for legacy registry bookkeeping. The new runtime additionally enforces the explicit UTC cutoff and earliest evidence time against its Timestamp pallet; block expiry is not a substitute for the UTC contract. Persist envelope bytes at the committed URI before submission. No automatic file upload or credential lookup exists.

The SQLite journal uses WAL, FULL synchronization, unique schedule requests and append-only audit/evidence rows. Persist submission intent before calling the transport. Reconcile finalized request storage after timeout/restart; an exact runtime retry is idempotent, while conflicting content is rejected. Repeated on-chain attempts can still incur ordinary transaction fees. The library's `Journal.submit` takes an explicit adapter. `rpc_adapter.py` verifies genesis, runtime version and metadata at one finalized block before reading request/prediction storage. Its mutation bridge permits only a caller-selected disposable loopback chain and supplied signer adapter; it refuses the production genesis. No embedded signing keys exist. The browser SDK exposes model/evaluation call builders and an account-change-aware session controller. Signed-chain lifecycle and actual SDK WebSocket submission/finality were exercised on an isolated four-validator chain. Actual injected-wallet/browser integration remains a release gate; neither dependency-injected tests nor the development-key transport proof substitutes for it.

Use `--fixture` for generated test observations. Never relabel them as real weather/model results. The included historical/future-date fixtures are synthetic only. `score` compares independent observations against both candidate and baseline; unsuccessful forecasts remain visible. Evidence created locally is labelled **prepared**, not on-chain validated. The supported history view exposes schedules, missed/failed attempts and all evidence revisions; `reconcile` now verifies finalized evidence storage against the prepared hash, reviewer and outcome before counting it in validated metrics. Real operator/collector commissioning and browser integration remain necessary before a deployed performance service can be claimed. ModelStats retains original registry counts; corrected comparative metrics must be derived from the evidence history, without erasing originals.

## Runtime financial policy and recovery

`FinancialModesAllowed=false` is a compiled runtime policy. Root configuration calls cannot enable financial flags; tokenization, approvals/transfers, stakes, side positions, proposals and disputes reject inside the pallet, including bypass-filter dispatch. Existing model/prediction/token IDs and old financial encodings remain. Claims/withdrawals and bond refunds can use historical state even with activation flags disabled; no new fraudulent-bond penalty is permitted by the nonfinancial policy. Existing Root runtime replacement/raw storage powers are not removed.

A **fresh finalized liability inventory is mandatory before adoption**: passive reserves/claims, side escrow/claims, unresolved bonds, settlement states and pool/treasury floors. Retained block1672 showed empty AI state but is not a current inventory. Current native recovery tests do not make MAX-gated historical claim calls usable in signed blocks; measure required recovery paths, or prove and enforce the applicable zero-liability upgrade precondition before deployment. Do not disable valid claims merely to activate evaluation. New registry calls charge ordinary transaction fees and introduce no explicit storage deposit; operator admission and bounded record/revision limits still matter for storage.

Funded-market code and prior tests are preserved behind the policy boundary. Its 1,010 ETKN proposal is historical, unapproved, unenforced and irrelevant to acceptance of this nonfinancial pilot. Any later financial activation is a separate jurisdiction-specific legal, operational and runtime decision.

## Complete service-contract rehearsal and evidence-reader repair

The allocator integration evidence now includes57 offline synthetic signed Wasm blocks executing the unchanged06:00 submission cutoff and14:00 outcome window, manifest registration/independent approval, prediction/idempotent retry, early evidence rejection, an ordinary losing forecast, correction and duplicate rejection. A separate actual four-validator/extension lifecycle remains retained; synthetic timestamps and the offline finality adapter are not independent GRANDPA finality or real weather performance. The service journal demonstrates response-loss/restart reconciliation without duplicate submission and checks both actual Wasm-produced evidence revisions before reporting metrics.

This rehearsal found and fixed a real reader defect: EvaluationEvidence uses Blake2_128Concat for prediction ID and **Twox64Concat for its u32 revision**. Previously the reader used Blake2_128Concat twice, silently failing to find existing revisions. Actual Wasm storage-key vectors now protect this integration;13 operator tests pass. Original failed forecasts and corrected metrics remain separately visible. Production model/operator/reviewer/artifact hosting and on-time operational observation remain commissioning requirements, not a reason to disable all AI functionality.

### Live source pagination correction — 20 September 2026

The live NWS KJFK response can include a continuation cursor even for a short interval. The previous single-page collector refused these valid responses. Collection now follows only HTTPS links on the same NWS station path, with at most eight pages,4 MB/page and16 MB total, reverse chronological progress checks and bounded request time. It retains the requested half-open interval, stops only at source exhaustion or after crossing its lower bound, saves original page bytes/hashes and publishes a normalized complete-interval document. Page/time/byte limits and unsafe or non-progressing cursors fail closed. Conflicting observations remain available for the established conflict filter.

Twenty operator/collector tests pass, including seven focused pagination cases. Actual public KJFK input/outcome acquisition also passed from RPC1 after the correction; this is data-source integration evidence, not an on-time prediction, independent reviewer control or finalized production performance. Source pages and the correction diff are retained under the commissioning-decision review. The runtime, SDK and their completed validation are unchanged.

# V14 managed assets and collections — development implementation

Pallet index27, `EraV14AssetAllocator`, integrates the adopted V1 asset contract with native Assets/Nfts. The spec16 creation-control successor is deployed. Historical current-genesis evidence justified the one-time initializer's asset and collection cursors `Some(1)`/`Some(1)`; its finalized execution, founder funding and the approved collection 1/three-item NFT commissioning passed. The original genesis, existing indices0–26, account records and native Assets/Nfts encodings remain unchanged. `EraV14AssetsApiV1` version1 is additive; retain its frozen wire format through at least the next two spec transitions (15→17). Collection0 and other reserved IDs remain preserved in native storage but are outside this V1 admission contract.

Root initialization is explicit, bounded and one-time. It requires nonzero historical-evidence commitment and approved high-water marks; it does not scan history, fill gaps, create assets or transfer funds. Only a canonical FRAME version0 marker may precede initialization. Unknown/orphan entries reject. A current empty backend does not establish that an ID has never been used. The accepted body audit proved gapless current-genesis coverage through the closure marker at block 334622 and supported both cursors at 1; finalized initializer block 335245 stored the exact evidence commitment. The earlier historical-proof requirement was satisfied, not waived.

Root grants one next-asset permit (creator and approved positive minimum balance) and one next-collection permit. Signed creation specifies issuer, administrator and freezer separately, consumes the permit, reserves10ETKN, creates the backend object and advances its cursor atomically. Managed minting requires the collection issuer, charges1ETKN native item deposit and allocates the next item. Exhausted cursors store `None`; failed calls roll back permits, deposits, backend state, events and cursors. Burning does not recycle IDs. All three managed collection roles remain present and mint mode stays issuer-only without a configured mint price. Existing object admission is explicit and preserves records. The spec16 cutover closed ordinary legacy asset/collection creation atomically before initialization; afterward the owning creation origins require the allocator guard, including bypass-filter dispatch. Managed item creation is guarded inside the owning NFT mutation helper. Retained Root raw-storage/runtime powers are not removed.
